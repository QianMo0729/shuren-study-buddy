# 运维与后台操作手册

给接手技术维护和参与审核的同学看。前半部分是后台怎么用（审核小组都要看），后半部分是服务器怎么维护（技术组看）。活动规则本身见 [活动规则](活动规则.md)，网站上的 `/rules` 页面与它一致。

## 一、角色与授权

| 角色 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 管理员 | 全部审核操作；修改活动设置与巡查周期；查看用户名单（含姓名、学号）；授权审核员或管理员 | — |
| 审核员 | 主页 / 招募 / 社区内容审核与撤下；处理举报；抽检、判无效、复核申诉；审核 Bonus；取消或恢复评奖资格；编辑私聊敏感词 | 改设置、看用户名单和学号、授权 |
| 同学 | 普通功能 | — |

**添加审核员**（不需要改服务器、不需要重启）：

1. 对方先用自己的校园邮箱激活账号；
2. 管理员进入「管理后台 → 审核小组」，输入对方的校园邮箱，选「审核员」，点「授权」；
3. 撤销：在同一页面点该成员的「撤销」。

管理员也可以写在服务器环境变量 `ADMIN_EMAILS` 里（逗号分隔），这些账号每次登录都会自动成为管理员；从名单里删掉不会自动撤销，需要在「审核小组」里撤销。不能修改自己的角色，避免误操作把自己锁在外面。

**请每人使用自己的账号，不要共用。** 每个操作都会记录操作人，「处理记录」能查到谁在什么时间做了什么，「审核小组」能看到每人最近 7 天的处理量。

## 二、轮流监管

排班在群里或表格里约定（例如每人负责一周），网站不做排班表。建议节奏：

**每天（值班的人）**
- 打开「管理后台 → 概览」，看「待办」里的数字；
- 处理「举报处理」和「社区内容」里的待审核内容；
- 回复「抽检与申诉 → 申诉」里不是自己判的申诉（申诉要在 48 小时期限内处理完）。

**每周一（值班的人）**
- 系统会自动生成上一周的抽检名单（随机抽取 + 系统标记）。在「抽检与申诉 → 待抽检」里逐条看，先看「系统标记」的；
- 处理「Bonus 审核」；
- 看一眼「搭子榜」后台版，留意分数异常高或无效次数多的组合。

**赛季结束、发奖前（管理员）**
1. 「搭子榜」点「复核获奖组合」，系统把获奖名次内所有组合的计分打卡加入抽检；
2. 审核小组把这些打卡全部看完（至少两人分工，避免一个人既判无效又复核申诉）；
3. 等申诉期结束、申诉处理完，再看最终名次；
4. 用后台搭子榜里的姓名和学号，按书院名单核对「是否为树仁学生」；
5. 名次边界上有并列时，公开抽签并录屏；
6. 导出获奖名单（目前在后台表格里手动记录）。

## 三、判定标准

### 撤下 还是 判无效？

- **撤下**：内容本身违规（广告、冒犯、泄露隐私、色情、政治敏感等），所有人都看不到。用于主页、招募、帖子、评论、打卡。
- **判无效**：打卡内容没问题，但不符合计分要求（看不到学习内容、看不清、翻拍、和说明不符、代打卡）。打卡照常显示，只是不计分，本人可以申诉。
- 两种都会自动给当事人发站内通知和邮件，写明时间和原因。

### 打卡什么时候判无效

照片要同时满足：① 能看到正在学的内容；② 本人的手或手臂入镜；③ 画面清楚。

| 情况 | 判定 |
| --- | --- |
| 打开的课本 + 握笔的手 | 有效 |
| 电脑上是题目或文档，手在键盘上 | 有效 |
| 只有桌面、天花板、窗外风景、奶茶 | 无效：画面中没有学习内容 |
| 很暗或很糊，认不出是什么 | 无效：画面看不清，无法判断 |
| 明显是对着屏幕拍的另一张照片 | 无效：翻拍或不是现场拍摄 |
| 说明写「复习线代」，照片是英语单词书 | 无效：画面与说明不符 |
| 两人的打卡来自同一台设备、背景和手完全一样 | 无效：疑似代打卡（可同时考虑取消资格） |
| 屏幕上是游戏或视频 | 无效：画面中没有学习内容 |
| 只拍了书，没有手 | 原则上无效；第一次可以只提醒、不判无效，由值班的人统一口径 |

**系统标记只是提示。** 两人在同一张桌子学习，提交时间相差几秒很正常；一个人借同学的手机登录过，也会出现「同一台设备登录过」。要看照片判断，拿不准时先判「有效」，在群里讨论。

### 申诉

- 申诉只能由**另一位**审核员处理，系统会挡住原来判无效的人；
- 「撤销，恢复计分」：照片其实符合要求；「维持无效」：说明理由（会告诉本人）；
- 复核结果是最终结果，每条打卡只能申诉一次。

### 取消评奖资格

- 自动：一个组合累计 3 次无效打卡（后台可调），自动不能参与评奖；
- 手动：确认代打卡、一人操作两个账号等作弊行为时，在「搭子榜」里点「取消资格」并写明原因，两人都会被取消且收到通知，换搭子也不能恢复；有误时可以「恢复资格」。

### 内容撤下的处罚

第 1 次撤下并说明原因；30 天内第 2 次撤下并再次提醒；30 天内第 3 次，或骚扰、色情、泄露隐私、政治敏感等情节严重的，撤下并取消本赛季评奖资格，必要时转交书院。撤下理由尽量从固定选项里选，保持口径一致。

### Bonus

按 [活动规则 · 第六条](活动规则.md#六bonus学习分享) 审核。字数和图片系统发帖时已经检查过，审核员主要看：是不是和学习有关、是不是原创、有没有写两人怎么一起完成的。不通过时要选或写原因。

### 私聊举报与敏感词

- 管理员看不到私聊，只有被举报时才看到被举报消息和它前后各 20 条对话（举报那一刻的快照）。核实后，私聊消息没法撤下，可以对当事人的主页、内容做处理，或线下联系，最后在「举报处理」里标记为已处理。
- 「敏感词」页可以编辑词库，每行一个词，保存后立即生效。政治敏感类直接拦截；色情、血腥、暴力发送前提醒，对方看到提示。不要加「政治」「血」这类太宽的词，会误伤「考研政治」等正常内容。改之前可以在页面底部「试一试」。

## 四、活动设置（管理员）

「管理后台 → 活动设置」可以改：赛季起止日期（开始必须是周一、结束必须是周日）、时间窗、每周上限与阶梯分、计分打卡的说明字数、抽检比例、获奖组合数、申诉期限、无效次数上限、Bonus 分值与上限。

积分不单独存储，每次都从打卡记录重新算，所以**改设置会影响已经结束的周**。赛季中途尽量不改计分规则；确实要改时先在群里公告。网站的规则页会自动显示新数字，`docs/活动规则.md` 需要手动同步。

## 五、服务器维护（技术组）

部署方式和环境变量见 [部署说明](deployment.md)。以下用 `<服务名>`、`<数据目录>` 代指实际的 systemd 服务名和 `DATA_DIR`，请交接时补上真实值。

**常用操作**

```sh
systemctl status <服务名>          # 是否在运行
systemctl restart <服务名>         # 重启（更新代码后）
journalctl -u <服务名> -n 200      # 最近日志；搜索 [audit] 看抽检定时任务、[mail] 看邮件失败
curl --fail http://127.0.0.1:8787/api/auth/me   # 本机自检，返回 {"user":null}
```

**更新版本**

1. 备份数据库与 uploads（见部署说明「验证与更新」，用 SQLite backup API，不要只复制正在运行的 `app.db`）；
2. 拉取代码、`npm ci`、`npm run build`、`npm test`；
3. 重启服务。新增的数据表和字段会在启动时自动创建，不需要手动迁移；
4. 用浏览器检查首页、登录、匹配推荐、搭子榜、管理后台。

**数据都在 `<数据目录>` 里**：`app.db`（数据库）和 `uploads/`（图片与打卡照片）。不要把它们放进代码目录或 Git。

**定时任务**（应用内自动运行，不需要 cron）

- 每小时：生成到期的每周抽检名单；删除超过 180 天的设备记录；
- 上传文件清理：见 README「旧数据升级」第 7 条。

**常见问题**

| 现象 | 处理 |
| --- | --- |
| 同学说收不到邮件 | 日志搜 `[mail]`；确认 `RESEND_API_KEY`/SMTP 配置；站内通知不受影响 |
| 同学说积分不对 | 后台「搭子榜」展开该组合的「每周明细」，对照打卡时间；常见原因：两人打卡相差超过 30 分钟、跨天、说明不到 5 个字、打卡被判无效或撤下、还在绑定后的第一周 |
| 同学说找不到对方的 ID | 对方主页要已发布；被排除的看不到；ID 是完整昵称（如「白鹭KLM23」）或末尾 5 位编号 |
| 搭子榜没更新 | 榜单只统计已结束的周，周一 0 点后才包含上一周；判无效、撤下、改设置后立即重算 |
| 新的审核员看不到后台 | 确认对方已经激活，并在「审核小组」里授权；让对方刷新页面 |
| 磁盘快满 | `MIN_FREE_DISK_MB` 以下时会暂停接收图片和打卡；清理日志或扩容 |

**交接清单**：服务器登录方式与权限、`<服务名>`、`<数据目录>`、环境配置文件位置（含 `CODE_PEPPER`、邮件服务密钥，不要发到群里）、域名与证书续期方式、备份存放位置、GitHub 仓库权限、管理员账号名单。
