# 树仁搭子：功能复核与精简建议

本次对照用户提供的审核、检索要求，检查当前 README、设计说明及前后端代码，并参考同类产品官方介绍。这里只形成评审建议，没有修改业务功能。结论来自静态代码核查；未验证生产环境配置、真实邮件收件或完整浏览器流程。

## 1. 总体判断

主体模块已具备：校园邮箱登录、个人主页、搭子广场、高级检索、活动大厅、个人中心、管理后台。优先工作应是补齐“找到合适的人 → 发起联系 → 双方确认 → 实际约成 → 更新状态”，以及“撤下 → 告知原因 → 整改/申诉 → 复核”的完整流程。

搭子广场和活动大厅都值得保留，分别承担“寻找长期学习伙伴”和“参加具体时间、地点、目标的招募”。收藏、举报、共同学习时间、站内通知已经存在，不应重复作为新功能开发。

## 2. 原要求覆盖情况

| 要求 | 当前状态 | 需要明确或补齐的部分 |
| --- | --- | --- |

## 3. 上线前优先处理的确定问题

### A. 匿名与联系方式相冲突

学校邮箱由学号组成，邮箱展示默认开启。任何登录用户点击获取联系方式，接口就会返回该邮箱。因此，卡片隐藏学号仍无法保证对陌生同学隐藏学号。

建议默认不公开学校邮箱，新增轻量联系申请：附一句学习目标、预计时间，对方可接受或拒绝；接受后由本人选择交换联系方式。明确提示交换学校邮箱会暴露学号。拒绝后限制重复请求，提供拉黑。无需先建设完整即时聊天系统。

原始课表截图也可能含姓名、学号，不应默认向其他同学展示。现有“可共同学习时间格”已能支持匹配，可取消公开课表截图或将其留作私有辅助材料。

依据：`shared/profileRules.ts:4`、`server/auth.ts:94`、`server/routes/profiles.ts:157`、`src/components/ProfileDetail.tsx:205`。

### B. 管理员撤下后，用户可以直接再次发布

主页发布接口直接清除撤下状态，不要求修改内容或管理员复核。同一违规主页可以立即回到广场。

建议：本人主动撤回可自行恢复；管理员撤下则保留状态，修改后提交复核，通过才恢复。撤下通知附具体原因、时间及可用的申诉入口或学发联系方式。活动和主页使用一致的处理规则。

依据：`server/routes/profiles.ts:43`；活动编辑不会清除撤下状态，见 `server/routes/posts.ts:160`。

### C. 管理员权限缺少撤销闭环

登录同步角色仅将名单内账号升级；从配置名单移除后，数据库中的管理员权限不会自动撤销。

建议补明确撤权机制，并使已登录会话及时失去管理员权限；交接记录保留操作人。依据：`server/routes/auth.ts:32`。

### D. “搭子特点”的检索对象错位

表单填写的是“你希望你的搭子有哪些特点”，检索却将这些值当成候选人的特点。检索“守时靠谱”实际找到的是“希望别人守时靠谱”的人。

建议拆分“我的学习习惯”和“对搭子的期待”，或先移除这个模糊的检索条件。不要把自报偏好包装成经过验证的个人品质。

依据：`src/pages/EditProfile.tsx:387`、`src/components/AdvancedSearch.tsx:21`、`server/search.ts:102`。

### E. 活动目前只有表达兴趣，没有正式报名

“我感兴趣”可添加或取消，并通知发起人，但没有待确认、已加入、拒绝、退出等参与状态。人数是展示字段，不限制感兴趣人数；这对“表达兴趣”本身合理，却不能被当作实际报名名额。目前卡片还会按感兴趣人数判断“已满”，容易使用户误以为已经成团。时间是自由文本，无法据此可靠地自动到期；修改、结束、删除活动也不会通知感兴趣的同学。

建议保留收藏式的“感兴趣”，另设“申请参加”，由发起人确认。首版支持人数上限、退出、开始/结束日期、到期停止招募，以及改期/取消通知；先不加候补排名、签到积分等复杂流程。

另有三处联系断路：主页允许不留任何联系方式，平台又没有站内联系申请；未公开主页的同学可以点感兴趣，却会从参与者展示列表中被过滤；发起人撤回主页后，活动仍可继续展示但无法通过主页联系。活动联系应基于参与关系，只向必要对象展示简要资料，不必强制向整个广场公开完整档案。

依据：`server/routes/posts.ts:66`、`:76`、`:135`、`:160`、`:185`；`server/routes/profiles.ts:56`；`src/components/PostCard.tsx:64`；`src/components/ProfileDetail.tsx:322`。

### F. 其他上线边界

- 文件访问接口只检查登录和文件存在，已知原图链接在内容撤下后仍可访问，应联动所属内容的可见性。依据：`server/routes/misc.ts:39`。
- 学校邮箱验证能证明掌握该邮箱，不能验证自由填写的真实姓名。个人资料里的学号还允许另填，应绑定已验证邮箱，调整“实名核验”表述。依据：`server/routes/profiles.ts:22`、`shared/profileRules.ts:29`。
- 邮件已有发送状态记录，但没有失败重试/补发。不能用“已撤下”代替“已发信”，更不能将 SMTP 接收成功等同于用户实际收到。依据：`server/mail.ts:28`、`server/routes/admin.ts:124`。

## 4. 建议补充的平台能力

| 优先级 | 功能 | 最小可用范围 |
| --- | --- | --- |
| 第一批 | 联系申请与拒绝/拉黑 | 双方同意再交换联系方式，限制重复请求，个人中心可查看进展 |
| 第一批 | 活动参与管理 | 申请、确认、退出、名额、到期、变更通知 |
| 第一批 | 整改复核和申诉 | 违规内容不能自行恢复；用户知道原因和处理进度 |
| 第二批 | 目标更明确 | 课程/考试/项目、近期目标、频率、预计持续多久；优先于毕业后的规划 |
| 第二批 | 找搭子状态与有效期 | 现有状态联动检索；暂停者默认不推荐；长期未更新提醒确认，不直接删除 |
| 第二批 | 搜索解释与条件保留 | 展示“符合 3/4，地点不符”；返回广场保留上次条件；没有结果时说明可放宽哪项 |
| 第二批 | 账户退出与数据清理 | 注销入口、撤回公开内容、必要审核记录保留规则；与普通退出登录区分 |
| 第二批 | 学发运营记录 | 负责人、开始/完成巡查、未处理举报、待复核数；举报结果反馈 |
| 规模增长后 | 列表分页和运营统计 | 关注有效联系、确认参加、长期未回应、举报处理时间；不要只看浏览量 |

目前已有暂停展示入口和状态标签，建议是让它们影响推荐与联系，而非重复增加一个按钮。周期可以由学发按活跃人数、新增内容和举报量调整；小规模先采用固定周期，不需要自动计算一个复杂周期公式。举报应及时处理，不等到下一轮巡查。

## 5. 建议固定的检索口径

1. 只统计实际填写的条件。“皆可”“不限”和空条件不计分母；零条件时展示普通列表，不显示虚假的匹配百分比。
2. 一类属性算一项。例如地点选择图书馆、书院自习室，候选人符合任一地点即该项命中，不按选项数量加分。
3. 标准检索必须严格过半：1 项需 1 项；2 项需 2 项；3 项需 2 项；4 项需 3 项；5 项需 3 项。实现方式为 `floor(N / 2) + 1`。
4. 按符合项数降序；并列可按共同学习时间、资料更新等排序。不要把“符合 3/4”称为“约成概率 75%”。
5. 为时间、必要地点等保留“必须符合”；“排除”作过滤，不增加符合项。其余为普通偏好。全部设成必须会缩小结果，应在界面说明。
6. “放宽检索”必须由用户主动触发并清楚标注，不能静默把少于半数的结果混入标准结果。当前“至少符合 N 项”建议移至这里。
7. 区分“我的学习属性”和“我希望对方具有的属性”；双向意愿与单向条件符合是两个概念。

示例：专业、性别、学习类型都符合，但唯一可接受的学习时间完全不重合。按普通四项计分会有 3/4，却未必能约成。用户可把时间设成必须条件，而不是提高 MBTI 等次要条件权重来掩盖这个问题。

## 6. 可以精简或后置的内容

- **减少必填项**：未来规划、希望搭子特点可选填；首轮围绕近期学习目标、时间、地点、学习方式。姓名、学号若保留用于管理，应私有且用途明确。
- **折叠次要筛选**：专业/年级等依场景使用；MBTI、体育、艺术和未来规划放入“更多偏好”。高级检索保留给需要它的人，普通入口先给常用条件。
- **降低类型测试门槛**：保留四种学习方式及文字解释，小测验可跳过；不把类型当作心理测评结果或固定人格。
- **减少原始课表公开**：已存在学习时间格，原图增加隐私风险和填写负担。
- **简化保存发布**：若原策划允许调整，可合并为“保存并发布”，保留独立“存草稿”，减少“保存→上传→确认”的重复动作。已发布内容仍需区分编辑与受处罚后的复核。
- **保留视觉辨识度，缩减重复装饰**：保留树仁绿、随机昵称、物种图版和小树人；卡片优先呈现近期目标、共同时间和是否正在找搭子。完整物种名录和拉丁学名可降低层级。
- **首版不增加**：完整聊天/视频自习、AI 人格匹配、积分商城、公开人气/信用排行榜、朋友圈、实时定位。需要有人维护、有人使用后再决定。

## 8. 下一轮修改的验收重点

- 非管理员无法撤下；撤权后原登录会话也无法继续管理。
- 被管理员撤下的主页不能直接发布；修改后提交复核，批准后才恢复。
- 默认不向陌生用户暴露学号邮箱；拒绝或屏蔽后不能继续获取未授权资料。
- 4 项条件仅命中 2 项不进入标准检索；命中 3 项进入；多选地点仍只算 1 项。
- “本人特点”与“期望特点”不会在检索中混淆。
- 活动达到确认名额时无法超额确认；退出可释放名额；改期、取消通知已确认参加者。
- 活动参与者有可用的联系流程，不因未向广场发布主页而消失。
- 邮件发送失败有可见状态和补发路径；巡查记录区分开始与完成。

建议顺序：先修审核与匿名问题，再补联系及活动确认流程，随后优化检索与填写负担，最后根据真实使用情况调整视觉和扩展功能。
