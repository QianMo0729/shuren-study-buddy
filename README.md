# 树仁搭子 · 学习搭子匹配系统

在线访问：**[pair.moorn.online](https://pair.moorn.online/)**

面向南方科技大学学生的学习搭子平台。学生验证校园邮箱并设置密码后，先完成个人资料、学习目标、时间安排和学习性格问卷。界面分为四个部分：

1. **匹配推荐**（`/match`）：一次弹出一张推荐卡片，可选「感兴趣」「不感兴趣」或「稍后再看」；按双向契合度排序，并根据每个人的选择个性化调整。另有按契合度排序的列表视图。
2. **校园社区**（`/community`）：聊天区（发帖分享生活、评论、点赞）、打卡区（网页实时拍照，服务器盖位置与北京时间水印）和招募（原活动大厅）。搜索帖子时可切换到高级检索，按条件找帖子或找同学。
3. **私聊**（`/messages`）：只有互相感兴趣的两人可以私聊，并在聊天中决定是否交换联系方式。
4. **我的**（`/me`）：资料与问卷、推荐偏好（不感兴趣、已排除）、我的内容、通知与账号设置。

本版按照《搭子匹配系统功能设计_排版优化版》重构。账号流程采用用户指定的 Resend 邮箱验证码激活与自主设置密码，不生成初始密码。当前版本已部署到上方站点，IPv4、IPv6、HTTPS 与证书续期演练均已验证；邮件服务器认证通过，实际收件仍需单独验收。

## 本地运行

需要 **Node.js ≥ 22.13**，数据库使用 Node 内置 `node:sqlite`。

```sh
npm install
cp .env.example .env
npm run dev
```

前端为 `http://localhost:5173`，API 为 `http://localhost:8787`。不配置发信凭据时，本机开发可获取测试验证码；生产环境始终禁止验证码回显。

```sh
npm run seed       # 可选，仅供本地演示
npm test           # 自动化验证，使用隔离的临时数据库并关闭真实发信
npm run typecheck
npm run build
```

演示管理员学号为 `12310000`，空白演示学号为 `12210001`，二者需要通过「激活账号」设置自己的密码。演示同学账号各自带有一个随机生成、不会显示的密码（因此会出现在匹配推荐中）；如需以演示同学身份登录，请在登录页使用「找回密码」通过邮箱验证码重设。没有统一演示密码。演示数据还包含若干社区帖子与评论，但不包含打卡（打卡照片必须实时拍摄）。`npm run seed -- --reset` 会清空所配置的数据目录中的数据库内容，只能用于本地演示。不要将本机 `.env` 或 `data/` 放入生产发布包。

## 账号与邮件

- **首次激活**：输入 8 位数字学号，验证码发送至 `<学号>@mail.sustech.edu.cn`。验证通过后，两次输入自己的新密码，完成激活并进入问卷。
- **以后登录**：使用完整校园邮箱与密码。未完成问卷的账号先进入问卷引导；完成问卷后进入匹配推荐。
- **忘记或修改密码**：通过校园邮箱验证码重新设置密码，成功后全部旧会话失效，需重新登录。
- 密码至少 8 个字符，包含英文字母与数字，最多 72 个 UTF-8 字节；服务端保存 bcrypt 哈希。
- 验证码与激活凭证有效期为 10 分钟、只能使用一次。验证码区分激活与重置用途；同一邮箱同一用途发送间隔 60 秒，每小时最多发送 5 次，单个验证码最多试错 5 次。登录、发码等接口另有频率限制。
- 验证邮箱本身不会获得登录态，必须完成密码设置。旧版验证码直接登录接口返回 410。
- Cookie 为 HttpOnly、SameSite=Lax，HTTPS 环境附带 Secure；认证响应不缓存。

推荐在私有环境文件中配置：

```dotenv
RESEND_API_KEY=
MAIL_FROM=no-reply@your-verified-domain.example
APP_URL=https://your-site.example
ADMIN_EMAILS=
```

将实际 API Key 填入私有配置，发件地址须使用自己的已验证域名。配置完整时优先通过 Resend API 发信；未配置 API 时可沿用 Resend SMTP：

```dotenv
SMTP_HOST=smtp.resend.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_REQUIRE_TLS=true
SMTP_USER=resend
SMTP_PASS=
MAIL_FROM=no-reply@your-verified-domain.example
```

API 发送失败不会自动切换 SMTP，避免重复投递。邮件包括激活验证码、重置验证码、互相感兴趣提醒、交换联系方式申请提醒与管理员撤下通知。生产未配置邮件服务时，发码返回 503；投递失败返回 502，未送达验证码会失效。本地开发日志不代表真实邮件送达。

`ADMIN_EMAILS` 是逗号分隔的完整校园邮箱列表。名单内账号完成激活或密码登录后获得管理员角色；从名单移除不会自动撤销数据库中已有管理员权限。

## 资料问卷与发布

问卷按 A–G 七个模块组织：

| 模块 | 内容 |
|---|---|
| A · 身份与展示 | 系统固定随机昵称、真实姓名、自动获取的学号、微信与 QQ、是否在双方确认后交换校园邮箱 |
| B · 基础画像 | 性别、年级、自由填写的专业 / 院系，均为选填 |
| C · 状态与目标 | 生活照片、近期学习目标、**具体科目 / 课程 / 考试**（最多 8 项）、**目标日期**、多选目标对应的补充内容、卡片上的一句话描述、目前状态 |
| D · 时间、地点与方式 | 我的地点与期望地点、**学习形式**（线下 / 线上 / 都可以）、我的空闲时间与期望时间、共同学习方式、学习模式、频率与单次时长、**希望搭子的性别** |
| E · 学习性格 | 7 道 1–5 分小题（学习时的交流、能接受的环境声音、守时、计划性、学习之外一起玩的意愿、需要被督促、愿意督促对方）、MBTI、雷区 |
| F · 学科与期待 | 对搭子的期待、自我介绍 |
| G · 补充与隐私 | 兴趣、照片展示意愿、四项隐私确认 |

发布需完成真实姓名、近期目标、地点、空闲时间、共同学习方式和四项隐私确认。新增的科目、目标日期、学习形式、希望搭子性别和学习性格都是选填，但会明显提高推荐准确度，问卷与匹配页都会提示补充。昵称固定分配，学号由登录邮箱派生，不能通过表单改写。

时间表为 **7 天 × 9 个时段**：08–10、10–12、12–14、14–16、16–18、18–20、20–22、22–24，以及当日 00–08 的通宵时段。填写期望搭子的时间后，与自己的实际时间取交集作为对比范围；不填写时使用自己的全部空闲时间。

填写过程中可以「保存草稿」；点击「提交问卷并匹配」时，先校验必填内容，确认公开范围后保存并发布，再进入匹配推荐。完整问卷保存为草稿即可标记为已完成，但必须确认发布后才会参与推荐。保存已公开资料时，如果删除必填内容或撤销隐私确认，主页会自动撤回。

## 匹配算法（rules-v2）

实现见 `server/recommendations.ts`，结果确定、可解释，**分数表示问卷契合程度，不是成功匹配概率**。

**硬条件（双向，任一不满足就不推荐）**：

- 希望搭子的性别：一方指定男 / 女时，另一方的性别必须一致（未填性别视为不满足）；「皆可」不限制。
- 学习形式：只线下与只线上互斥，「都可以」或未填兼容两者。
- 共同时间：双方有效时间（实际空闲 ∩ 期望时间）没有共同时段时不推荐。

**七个维度，每个维度分别计算两个方向**：「TA 符合你的期待」与「你符合 TA 的期待」。

| 维度 | 权重 | 规则 |
|---|---:|---|
| 共同时间 | 30 | 共同小时 ÷ 我每周想学的时长（频率 × 单次时长，缺失按 4 小时），封顶 1。比我更有空的人不扣分；通宵在评分时最多按 2 小时计 |
| 学习内容 | 22 | 具体科目经全角兼容、大小写、空白标准化，并按严格的科目等价表（`shared/subjects.ts`，如 线代 = 线性代数）比较，包含关系也算同一科目：同科目 0.75 + 0.25 × 重合比例；双方都填了科目但不同 = 0.5 × 目标大类重合；任一方没填科目 = 0.8 × 目标大类重合。重合比例用「共同项 ÷ 较少一方的项数」，多选不吃亏。考试日期相差 21 天内额外 +0.05 |
| 学习性格 | 20 | 交流、环境声音、守时、计划性、学习外社交：越接近越好（1 − 差值/4）；督促是互补项：我需要被督促的程度应由对方愿意督促的程度满足。双方都填 MBTI 时按 E/I、J/P（各 1）与 S/N、T/F（各 0.5）一致程度计入 20%。雷区「过度社交 / 全程沉默 / 迟到爽约」与对方答案冲突时该方向 ×0.6 并给出提醒 |
| 学习方式 | 10 | 相同 1；「灵活」与任意 0.7；安静–打卡、讨论–打卡 0.5；安静–讨论 0.15 |
| 学习地点 | 8 | 我期望的地点（没选期望地点时用我自己的地点，补充文字只作追加）与对方实际地点有交集或任一为「不限」为 1，否则 0.25；任一方只线上学习时为 1 |
| 学习节奏 | 6 | 频率相同 1、相邻 0.6、「不定期」与任意 0.6、其余 0.2；单次时长相同 1、相邻 0.6、其余 0.3 |
| 兴趣 | 4 | 共同项 ÷ 较少一方的项数 |

**汇总**：任一方向缺少可比信息的维度按中性 0.5 计入（资料少的人不会因此分数虚高），并单独显示信息覆盖权重。每个方向先按权重加权平均；**共同时间、学习内容、学习性格任一项实际测得低于 0.6 时，再乘以 0.6 + (2/3) × 该项分数**（只用中性值补齐的方向不惩罚），避免核心短板被其他维度平均掉（时间、内容、性格都合适才算合拍）。总分取两个方向的调和平均 `2·S我·S对方 / (S我 + S对方)`，只有双方都满意才会高分。档位：总分 ≥ 80、核心维度都不低于 0.6 且信息覆盖 ≥ 80 为「很合拍」，≥ 65 为「较合拍」，其余为「可以聊聊」。每张卡片附最多 4 条理由和 3 条提醒。

真实姓名、学号、邮箱、联系方式、照片、自由文字期待与自我介绍不参与评分；性别只作为上述硬条件使用。

## 匹配推荐与个性化排序

- **候选人**：已激活并设置密码、主页公开未撤下、问卷完整、四项隐私同意完整、状态为「正在找搭子」或「已有搭子，仍可再约」。排除自己、任一方向的排除关系、已标记不感兴趣的、已标记感兴趣正在等待对方的、已配对的、3 天内选过「稍后再看」的、**已对我标记不感兴趣的**（静默）、旧版被拒绝的联系申请，以及不满足硬条件的人。
- **个人偏好模型**（`server/learning.ts`）：特征为 7 个维度的契合度、候选人的学习方式、交流强度、学习强度与是否同专业 / 院系；**不使用性别、照片、年级或昵称**。逻辑回归 `p = σ(b + Σ w(x − 0.5))`，先验权重为维度权重 × 0.08。每次需要时，从当前先验出发按时间顺序重放本人最近 500 次「感兴趣 / 不感兴趣 / 稍后再看」（样本权重 1 / 1 / 0.3；在线更新，学习率 0.35，向先验的 L2 回拉 0.04），因此撤销、改写、解除配对都能精确反映，少量点击不会推翻问卷结果。解除配对、排除等不是在卡片上做出的选择，不参与学习。全站反馈达到 200 条后，在响应之后异步用最近 5000 条反馈拟合全站先验，之后每新增 50 条重算一次。
- **排序**：`排序分 = (1 − α) × 契合度 + α × 100p`，α = 0.45 × min(1, 反馈次数 / 20)。近期登录过的人小幅前移，超过 30 天未登录或正在被大量请求的人后移。「对方已对我感兴趣」只影响谁能进入这一批卡片，不影响批内顺序，也不出现在返回的分数里，因此无法从卡片顺序推断谁对我感兴趣。每批卡片约 20% 的位置按日期确定性地从更靠后的排名中抽取（探索位），避免推荐越来越窄。
- **接口**：`GET /api/match/deck`（卡片，个性化）、`GET /api/match/ranked`（按契合度排序的列表，不含个性化）、`POST /api/match/feedback`、`DELETE /api/match/feedback/:targetId`（撤销）、`GET /api/match/feedback?action=`。兼容保留的 `GET /api/profiles/recommendations` 返回 ranked 的前 20 位。
- **互相感兴趣**：双方都选「感兴趣」时自动建立配对，双方收到站内通知，先选的一方另收到邮件，随后可以私聊。

## 私聊与交换联系方式

- 只有互相感兴趣的配对可以私聊；任一方可随时解除配对，聊天转为只读并不再推荐对方。排除对方也会关闭配对。
- 消息每条 1–1000 字，每分钟最多 20 条、每天最多 500 条；页面可见时每 4 秒拉取新消息，未读数显示在导航角标上。
- 交换联系方式在私聊中申请：必须存在活跃配对，申请方与同意方**都必须至少填写一种联系方式**（微信、QQ、手机、其他，或开启交换校园邮箱），从而不会出现同意后拿不到联系方式的情况。被拒绝 7 天后可以再次申请（排除再取消排除不会绕过这个等待）。配对解除后，交换同意随之失效、联系方式不再通过系统展示；重新配对后需要重新申请。重新配对不会再次发送「互相感兴趣」通知或邮件。
- 排除某人时，系统同时把排除者对对方的选择记为「不感兴趣」；取消排除后，需要在「我的 · 推荐偏好」中放回推荐才会再次出现。
- 举报私聊消息时，系统只把被举报的那条消息原文存入举报记录的独立字段，管理员看不到其他聊天记录；举报人填写的说明与留存原文分开保存，无法伪造。

## 校园社区

- **聊天区**：帖子标题选填（≤ 60 字），正文 1–2000 字，最多 4 张图片（本人上传的社区图片）。可编辑、删除自己的帖子，评论（1–500 字）、点赞，新评论会通知作者。帖子只显示系统昵称；作者主页对你可见时才能点进主页。
- **检索**：关键词检索帖子标题与正文（保留同义词扩展）。点击「高级检索」后可选择检索对象：
  - **帖子**：按标题 / 正文关键词，以及作者已公开主页中的专业、院系、性别、年级、学习方式、地点、目标、科目等条件检索；作者主页对你不可见时，作者条件一律视为未命中。
  - **同学**：原搭子检索，支持性别、专业、院系、年级、学习类型、地点、目标、科目、状态、时间、学习模式、频率、时长、兴趣及搭子期待等。
  - 科目条件与匹配算法使用同一套严格的科目等价表（`shared/subjects.ts`，如 线代 = 线性代数、雅思 = IELTS），不会把「刷题」「建模」这类检索同义词当成同一门课。
  - 两者都使用「加分 / 必须 / 排除」：精确匹配需符合超过半数的加分条件（`floor(n/2) + 1`），模糊匹配符合任意一项即可；「必须」与「排除」始终生效；结果按符合条件数排序。
- **打卡区**：见下文。可以选择所有同学可见，或仅互相感兴趣的搭子可见；显示连续打卡天数（按北京日期）。
- **招募**：原活动大厅，保留招募、编辑、结束、删除与感兴趣功能。

## 学习打卡与服务器水印

- 打卡页只通过 `getUserMedia` 调用摄像头实时拍照，**页面没有任何上传或相册入口**；`/api/uploads` 拒绝打卡照片。
- 摄像头开启后领取一次性拍照凭证（3 分钟有效、签发 0.5 秒后才能使用、只存哈希），提交时原子作废；服务器只接受 JPEG，拒绝带相机 EXIF 的图片，每天最多打卡 10 次。
- 服务器收到照片后，在**右下角**盖两行水印：地点（例如「南科大·琳恩图书馆」）和服务器收到照片时的 **北京时间**。水印使用 GNU Unifont 16px 点阵字形，**逐个像素绘制**：每个字形像素按照片中对应区块的平均亮度决定颜色，亮背景涂黑、暗背景涂白。像素块大小为 `max(2, round(短边 / 400))`，随后重新编码（同时去除照片元数据）。客户端提交的任何时间字段都会被忽略。
- 位置：浏览器定位只用于换算校园地点名称，**不保存经纬度**；未授权定位时水印为「未提供位置」，校外为「校外」。
- **上线前必须实地校准** `shared/campusPlaces.ts` 中的地点坐标（目前为估计值）。修改地点名称后需运行 `npx tsx scripts/gen-watermark-font.mjs` 重新生成点阵字形。
- 限制：网页无法从技术上证明照片一定是现场拍摄，脚本化客户端仍可能伪造画面或定位；以上措施只能大幅提高作假成本。

## 隐私与管理

照片默认私有，只有主动选择展示、发布主页并完成隐私同意后，其他登录同学才可访问。每次请求原图都会检查权限，图片响应为 `private, no-store`；主页撤回、管理员撤下、关闭照片展示或排除后，对相应同学的原图链接失效。本人和管理员保留查看权限；已被他人保存到设备的副本无法远程收回。

普通公开主页不返回真实姓名、学号或联系方式。真实姓名与身份信息供本人及管理员查看；联系方式须经过双方同意。隐私政策页面为 `/privacy`。

「我的」包含资料与问卷、推荐偏好（不感兴趣的同学可放回推荐、已排除的同学可取消排除）、我的帖子 / 打卡 / 招募 / 收藏、通知及账号设置。注销需验证当前密码，会撤回公开资料、招募、社区帖子、评论和打卡，删除推荐选择记录、私聊配对与消息、上传文件及相关私密资料，撤销会话和联系授权；用户行保留匿名编号以维持审核记录的引用关系，不再保留登录邮箱或密码。

管理员可查看待审核内容（主页、招募、社区帖子、评论、打卡）、处理举报（含私聊消息举报，只显示被举报消息的原文）、撤下 / 恢复内容，设置巡查周期，记录审核时间与原因，并向当事人发送邮件及站内通知。

## 旧数据升级

首次用本版启动已有数据库时会自动处理旧资料：

1. 保留账号 ID、昵称、文字、联系方式及上传引用，不创建默认密码。
2. 旧的无密码账号必须验证邮箱并设置密码，原来的无密码会话无法继续访问。
3. 资料迁移到 schema v2，旧目标与学习方式映射到新选项。
4. 旧 7×10 时间表只迁移能够完整覆盖新时段的选择，不扩大旧的空闲范围。
5. 旧主页暂时撤回，照片改为默认私有、隐私同意清空。用户检查迁移结果并逐项确认新隐私条款后重新发布。
6. v3 首次启动时，旧的联系申请自动转换一次：发起申请视为发起方「感兴趣」；已接受的申请视为双方感兴趣并建立私聊配对。转换完成后在 `settings` 中记录，之后的启动不会重复转换（否则会恢复用户撤销过的选择）。新增的问卷字段（科目、学习性格等）默认为空，不影响已发布主页的推荐资格。

**首次启动升级前，应备份数据库与 uploads。** 回退旧代码可能恢复旧的隐私行为，不能作为无损回滚方式；恢复数据应使用同一时间点的完整备份并按部署说明验收。部署与运行配置见 [部署说明](docs/deployment.md)。
