# 树仁搭子 · 学习搭子匹配系统

在线访问：**[pair.moorn.online](https://pair.moorn.online/)**

面向南方科技大学学生的学习搭子平台。学生验证校园邮箱并设置密码后，先完成个人资料、学习目标、时间安排和学习性格问卷。界面分为四个部分：

1. **匹配推荐**（`/match`）：每天最多推荐 5 位，北京时间零点更新，卡片与列表共用固定名单。左滑（←）表示「感兴趣」，右滑（→）表示「不感兴趣」，「稍后再看」（↓）存入独立待看列表；另有「找同学」（`/match/search`）与「稍后再看」（`/match/later`）入口。
2. **校园社区**（`/community`）：聊天区（发帖分享生活、评论、点赞）、打卡区（网页实时拍照，服务器盖位置与北京时间水印）和招募（原活动大厅）。帖子关键词与高级检索只检索帖子；查找同学使用匹配页的独立入口。
3. **私聊**（`/messages`）：只有互相感兴趣的两人可以私聊，并在聊天中决定是否交换联系方式。
4. **我的**（`/me`）：资料与问卷、私人课表、推荐偏好（感兴趣待回应、不感兴趣、已排除及稍后再看入口）、我的内容、通知与账号设置。

本版按照《搭子匹配系统功能设计_排版优化版》重构。账号流程采用用户指定的 Resend 邮箱验证码激活与自主设置密码，不生成初始密码。**2026-10-07 的七项改进已合并到 `main` 并部署至上方站点。** 邮件实际收件仍需单独验收。

## 本地运行

需要 **Node.js ≥ 22.13**，数据库使用 Node 内置 `node:sqlite`。

```sh
npm install
cp .env.example .env
npm run dev
```

前端为 `http://localhost:5173`，API 为 `http://localhost:8787`。不配置发信凭据时，本机开发可获取测试验证码；生产环境始终禁止验证码回显。

开发服务默认只监听本机（`127.0.0.1`），局域网内的其他设备无法访问。确实需要用手机等设备调试时，在 `.env` 中设置 `DEV_LAN=true` 再启动：此时前端对局域网开放、API 仍只监听本机，由开发代理转发。无论哪种方式，开发服务器都不会把数据目录、SQLite 文件、上传的图片和 `.env` 当作静态文件读出来；验证码回显只出现在本机浏览器打开的页面里（经代理进来的其他设备、省略来源头的脚本请求都看不到），验证码仍会打印在服务端控制台。

```sh
npm run seed       # 可选，仅供本地演示
npm test           # 自动化验证，使用隔离的临时数据库并关闭真实发信
npm run typecheck
npm run build
```

演示管理员学号为 `12310000`，空白演示学号为 `12210001`，二者需要通过「激活账号」设置自己的密码。演示同学账号各自带有一个随机生成、不会显示的密码（因此会出现在匹配推荐中）；如需以演示同学身份登录，请在登录页使用「找回密码」通过邮箱验证码重设。没有统一演示密码。演示数据还包含若干社区帖子与评论，但不包含打卡（打卡照片必须实时拍摄）。`npm run seed -- --reset` 会清空所配置的数据目录中的数据库内容，只能用于本地演示。不要将本机 `.env` 或 `data/` 放入生产发布包。

## 账号与邮件

- **首次激活**：输入 8 位数字学号，验证码发送至 `<学号>@mail.sustech.edu.cn`。验证通过后，两次输入自己的新密码，完成激活并进入问卷。
- **以后登录**：使用完整校园邮箱与密码。未完成问卷的账号先进入问卷引导；完成问卷后进入匹配推荐。
- **忘记或修改密码**：通过校园邮箱验证码重新设置密码，成功后全部旧会话失效，需重新登录。
- 密码至少 8 个字符，包含英文字母与数字，最多 72 个 UTF-8 字节；服务端保存 bcrypt 哈希。
- 验证码与激活凭证有效期为 10 分钟、只能使用一次。验证码区分激活与重置用途；同一邮箱同一用途发送间隔 60 秒，每小时最多发送 5 次，单个验证码最多试错 5 次。登录、发码等接口另有频率限制。
- 数据库只保存验证码的带密钥校验值（HMAC），密钥不在数据库里：只拿到数据库或备份无法穷举出验证码。密钥可用 `CODE_PEPPER` 配置；不配置时每次启动随机生成，重启后尚未使用的验证码失效，重新获取即可。
- 发码与校验接口不透露账号状态：学号是否已激活、邮箱是否有账号，返回的状态码、内容、冷却时间和输错验证码时的提示都相同。已激活的学号再次申请激活、或为没有账号的邮箱申请重设密码时，对应邮箱收到的是一封说明邮件（不含验证码），只有邮箱的主人能知道。
- 限流记录保存在内存中，条数有上限、过期清理按固定步数进行；含邮箱的限流键之前都有一道按来源地址的限额（IPv6 按 /64 归并），同一来源不能靠更换学号绕过。
- 验证邮箱本身不会获得登录态，必须完成密码设置。旧版验证码直接登录接口返回 410。
- Cookie 为 HttpOnly、SameSite=Lax，HTTPS 环境附带 Secure；认证响应不缓存。

推荐在私有环境文件中配置：

```dotenv
RESEND_API_KEY=
MAIL_FROM=no-reply@your-verified-domain.example
APP_URL=https://your-site.example
ADMIN_EMAILS=
```

将实际 API Key 填入私有配置，发件地址须使用自己的已验证域名。配置完整时优先通过 Resend API 发信；未配置 API 时可沿用 Resend SMTP：

```dotenv
SMTP_HOST=smtp.resend.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_REQUIRE_TLS=true
SMTP_USER=resend
SMTP_PASS=
MAIL_FROM=no-reply@your-verified-domain.example
```

API 发送失败不会自动切换 SMTP，避免重复投递。邮件包括激活验证码、重置验证码、互相感兴趣提醒、交换联系方式申请提醒与管理员撤下通知。生产未配置邮件服务时，发码返回 503；投递失败返回 502，未送达验证码会失效。本地开发日志不代表真实邮件送达。

`ADMIN_EMAILS` 是逗号分隔的完整校园邮箱列表。名单内账号完成激活或密码登录后获得管理员角色；从名单移除不会自动撤销数据库中已有管理员权限。

## 资料问卷与发布

问卷按 A–G 七个模块组织：

| 模块 | 内容 |
|---|---|
| A · 身份与展示 | 系统固定随机昵称、真实姓名、自动获取的学号、微信与 QQ、是否在双方确认后交换校园邮箱 |
| B · 基础画像 | 性别与年级必填，专业 / 院系从目录搜索选择（选填）；可独立关闭性别展示，隐藏后仍用于匹配偏好 |
| C · 状态与目标 | 生活照片、近期学习目标、**本学期课程清单与私人课表导入**、**具体科目 / 课程 / 考试**（Q7 最多 3 项重点）、**目标日期**、多选目标对应的补充内容、卡片上的一句话描述、目前状态 |
| D · 时间、地点与方式 | 我的地点与期望地点、**学习形式**（线下 / 线上 / 都可以）、我的空闲时间与期望时间、共同学习方式、学习模式、频率与单次时长、**希望搭子的性别** |
| E · 学习性格 | 7 道 1–5 分小题（学习时的交流、能接受的环境声音、守时、计划性、学习之外一起玩的意愿、需要被督促、愿意督促对方）、MBTI 类型选择、雷区 |
| F · 学科与期待 | 对搭子的期待（多选及补充）、自我介绍 |
| G · 补充与隐私 | 兴趣、照片展示意愿、四项隐私确认 |

发布需完成真实姓名、性别、年级、近期目标、地点、空闲时间、共同学习方式和四项隐私确认。科目、目标日期、学习形式、希望搭子性别和学习性格为选填。昵称固定分配，学号由登录邮箱派生，不能通过表单改写。

专业可按院系或关键词选择，尚未分专业可选择大类培养或暂未确定。明确的旧简称会规范为标准值，无法唯一确认的原文保留在草稿中，重新提交前需选择标准专业或清空这项选填答案。MBTI 提供类型选项，科研 / 竞赛、自学技能与搭子期待支持多选并补充文字，原有自由文字继续保留。

问卷中的本学期课程清单与 Q7 重点科目分别保存，都只能从标准目录搜索或选择。本学期清单可选最多 30 门校内课程，仅本人可见；Q7 从课表或课程 / 考试目录中挑选最多 3 项，用于匹配。课程按院系分类，备考按类别、考试和必要的等级分类；大学英语直接选择四级或六级。课程来源为学校公开课程目录，并用官方培养方案补充缺失条目，不表示已实时同步登录后的 TIS。目标日期以 `YYYYMMDD` 填写，最终提交时校验真实日期并转换为 ISO 日期；未填完的日期也能保存在草稿中。

用于学习匹配的空闲时间表为 **7 天 × 9 个时段**（与下述真实上课节次分开保存）：08–10、10–12、12–14、14–16、16–18、18–20、20–22、22–24，以及当日 00–08 的通宵时段。填写期望搭子的时间后，与自己的实际时间取交集作为对比范围；不填写时使用自己的全部空闲时间。

问卷按 A–G 分页，填写时自动保存本机备份和服务端独立草稿；草稿不会改变已发布资料，也不会解锁匹配（已发布的资料有未提交的修改时，保存提示会写明「提交后才会更新已发布的主页」）。篇幅大的选填项——本学期课表课程、期望对方的地点与时间——默认收起成一行并写明当前按什么默认值处理，填过或点开后才展开。本机备份只在修改还没有同步到服务器期间存在，同步后即删除；退出登录、会话失效、换号或注销后，本机上的问卷草稿和未发出的帖子草稿都会被清除，超过 7 天未同步的本机草稿不再恢复。完成 G 后集中列出缺失内容及对应模块和题号，全部通过后才显示「提交问卷并匹配」。提交会保存、发布并进入匹配推荐。未完成问卷访问匹配页时会显示小树仁提示页，不强制跳转。保存已公开资料时，如果删除必填内容或撤销隐私确认，主页会自动撤回。

## 私人课表与 TIS Excel 导入

在问卷 C 模块选择 TIS 导出的个人课表 **`.xlsx` 文件（最大 2 MB）**，浏览器本地解析后先预览，再校对课程、星期、起止节次、周次与地点，最后「确认并保存课表」。支持手动添加排课、同一单元格多次排课、合并去重、替换预览和时间冲突提示；解析失败或取消预览不会覆盖已保存课表。周次逐段解析，例如 `1,2-16双周` 会保留第 1 周及第 2–16 周中的双周。

私人课表独立保存，仅本人可见；原始 Excel、表内学生身份与教师信息不上传保存。无法对应标准目录的排课可保留原课程名并手动确认；更新问卷中的本学期课程清单时，只加入已对应标准目录的课程。保存课表不会自动修改公开问卷或 Q7 匹配重点科目，需另行确认更新并提交问卷。

电脑显示周课表，手机可按日查看；均可切换教学周。填写学期及可选的「第 1 教学周的周一」后可计算当前教学周；未填写首周日期时按第 N 周查看，不推测开学日期。最多保存 200 条排课，支持第 1–30 教学周。节次按本次确认的规则配置，每节 50 分钟：

| 节次 | 时间 | 节次 | 时间 |
|---|---|---|---|
| 1 | 08:00–08:50 | 7 | 16:20–17:10 |
| 2 | 09:00–09:50 | 8 | 17:20–18:10 |
| 3 | 10:20–11:10 | 9 | 19:00–19:50 |
| 4 | 11:20–12:10 | 10 | 20:00–20:50 |
| 5 | 14:00–14:50 | 11 | 21:20–22:10 |
| 6 | 15:00–15:50 | — | — |

第 11 节按相同休息规则推算。连续课程展示起止时间，包含中间课间。可在确认后从本人已勾选、愿意学习的空闲时间中扣除与课程重叠的整个匹配时段；不会把所有无课时间自动视为可学习时间。首版支持 Excel，尚不支持截图 OCR 或登录 TIS 自动同步。

## 匹配算法（rules-v2）

实现见 `server/recommendations.ts`，结果确定、可解释，**分数表示问卷契合程度，不是成功匹配概率**。

**硬条件（双向，任一不满足就不推荐）**：

- 希望搭子的性别：一方指定男 / 女时，另一方的性别必须一致（未填性别视为不满足）；「皆可」不限制。
- 学习形式：只线下与只线上互斥，「都可以」或未填兼容两者。
- 共同时间：双方有效时间（实际空闲 ∩ 期望时间）没有共同时段时不推荐。

**七个维度，每个维度分别计算两个方向**：「TA 符合你的期待」与「你符合 TA 的期待」。

| 维度 | 权重 | 规则 |
|---|---:|---|
| 共同时间 | 30 | 共同小时 ÷ 我每周想学的时长（频率 × 单次时长，缺失按 4 小时），封顶 1。比我更有空的人不扣分；通宵在评分时最多按 2 小时计 |
| 学习内容 | 22 | 标准目录科目按课程或考试标识精确比较，旧资料使用科目等价表（`shared/subjects.ts`）兼容。同科目 0.75 + 0.25 × 重合比例；双方都填了科目但不同 = 0.5 × 目标大类重合；任一方没填科目 = 0.8 × 目标大类重合。重合比例用「共同项 ÷ 较少一方的项数」，多选不吃亏。考试日期相差 21 天内额外 +0.05 |
| 学习性格 | 20 | 交流、环境声音、守时、计划性、学习外社交：越接近越好（1 − 差值/4）；督促是互补项：我需要被督促的程度应由对方愿意督促的程度满足。双方都填 MBTI 时按 E/I、J/P（各 1）与 S/N、T/F（各 0.5）一致程度计入 20%。雷区「过度社交 / 全程沉默 / 迟到爽约」与对方答案冲突时该方向 ×0.6 并给出提醒 |
| 学习方式 | 10 | 相同 1；「灵活」与任意 0.7；安静–打卡、讨论–打卡 0.5；安静–讨论 0.15 |
| 学习地点 | 8 | 我期望的地点（没选期望地点时用我自己的地点，补充文字只作追加）与对方实际地点有交集或任一为「不限」为 1，否则 0.25；任一方只线上学习时为 1 |
| 学习节奏 | 6 | 频率相同 1、相邻 0.6、「不定期」与任意 0.6、其余 0.2；单次时长相同 1、相邻 0.6、其余 0.3 |
| 兴趣 | 4 | 共同项 ÷ 较少一方的项数 |

**汇总**：任一方向缺少可比信息的维度按中性 0.5 计入（资料少的人不会因此分数虚高），并单独显示信息覆盖权重。每个方向先按权重加权平均；**共同时间、学习内容、学习性格任一项实际测得低于 0.6 时，再乘以 0.6 + (2/3) × 该项分数**（只用中性值补齐的方向不惩罚），避免核心短板被其他维度平均掉（时间、内容、性格都合适才算合拍）。总分取两个方向的调和平均 `2·S我·S对方 / (S我 + S对方)`，只有双方都满意才会高分。档位：总分 ≥ 80、核心维度都不低于 0.6 且信息覆盖 ≥ 80 为「很合拍」，≥ 65 为「较合拍」，其余为「可以聊聊」。每张卡片附最多 4 条理由和 3 条提醒。

真实姓名、学号、邮箱、联系方式、照片、自由文字期待与自我介绍不参与评分；性别只作为上述硬条件使用。

## 匹配推荐与个性化排序

- **候选人**：已激活并设置密码、主页公开未撤下、问卷完整、四项隐私同意完整、状态为「正在找搭子」或「已有搭子，仍可再约」。排除自己、任一方向的排除关系、已标记不感兴趣的、已标记感兴趣正在等待对方的、已配对的、仍在「稍后再看」列表中的、**已对我标记不感兴趣的**（静默）、旧版被拒绝的联系申请，以及不满足硬条件的人。
- **个人偏好模型**（`server/learning.ts`）：特征为 7 个维度的契合度、候选人的学习方式、交流强度、学习强度与是否同专业 / 院系；**不使用性别、照片、年级或昵称**。逻辑回归 `p = σ(b + Σ w(x − 0.5))`，先验权重为维度权重 × 0.08。每次需要时，从当前先验出发按时间顺序重放本人最近 500 条带特征的「感兴趣 / 不感兴趣」（样本权重均为 1；在线更新，学习率 0.35，向先验的 L2 回拉 0.04），因此撤销、改写、解除配对都能精确反映，少量点击不会推翻问卷结果。「稍后再看」是中性的待办操作，旧的稍后反馈特征也不参与学习；解除配对、排除等不是在卡片上做出的选择，同样不参与学习。有效全站反馈达到 200 条后，在响应之后异步用最近 5000 条反馈拟合全站先验，之后每新增 50 条重算一次。
- **每日名单**：北京时间每天首次领取时生成并持久化最多 5 位，同一天名单和顺序固定；卡片、列表、兼容接口、刷新和不同设备共用。候选不足时按实际人数生成，空名单也等到次日重建。感兴趣、不感兴趣、稍后再看与撤销不会补入新对象；撤销只可能恢复原名单中的同学。每次响应重新检查可见性、匹配资格及硬条件，撤回主页、排除或不再符合条件的同学即时隐藏且不补位。界面区分今日已看完与暂时没有合适候选。
- **排序**：`排序分 = (1 − α) × 契合度 + α × 100p`，α = 0.45 × min(1, 反馈次数 / 20)。生成新一天的名单时优先最近 7 天未曝光的合适同学，再结合问卷与本人偏好排序，不放宽硬条件；满足候选数量时最多保留 1 个确定性探索位。**别人的私密状态不参与排序**：单向感兴趣、最近登录及尚未回应的感兴趣数量均不用于排序。当天反馈学习影响后续名单，不即时改排当天名单；展示的问卷契合度仍按当前资料计算。
- **稍后再看**：`/match/later` 独立显示本人待办，直到本人表示感兴趣、不感兴趣或移除；不再按 3 天自动回流。支持查看主页和备注，已下线或不可见的主页暂不展示。主动「找同学」不受每日自动推荐额度限制。
- **接口**：`GET /api/match/deck`、`GET /api/match/ranked` 与兼容的 `GET /api/profiles/recommendations` 共用同一份最多 5 位的每日名单；`POST /api/match/feedback` 保存选择，`DELETE /api/match/feedback/:targetId` 撤销，`GET /api/match/feedback?action=` 查看本人的选择。
- **互相感兴趣**：双方都选「感兴趣」时自动建立配对，双方收到站内通知，先选的一方另收到邮件，随后可以私聊。

## 私聊与交换联系方式

- **私人备注**：在同学主页或私聊中设置备注名（最多 40 字）和说明（最多 300 字），可编辑或删除。推荐卡片、同学检索、待看列表与会话列表显示本人的备注名，并保留系统昵称以便辨认。备注仅本人可见，不通知对方、不参与匹配；排除关系与账号注销会遵循对应的访问和清理规则。
- 只有互相感兴趣的配对可以私聊；任一方可随时解除配对，聊天转为只读并不再推荐对方。排除对方也会关闭配对。
- 消息每条 1–1000 字，每分钟最多 20 条、每天最多 500 条；页面可见时每 4 秒拉取新消息，未读数显示在导航角标上。
- 交换联系方式在私聊中申请：必须存在活跃配对，申请方与同意方**都必须至少填写一种联系方式**（微信、QQ、手机、其他，或开启交换校园邮箱），从而不会出现同意后拿不到联系方式的情况。自己还没填时，申请或同意的那一步会就地给出微信 / QQ 输入框，保存后接着完成刚才的操作（`PUT /api/profiles/me/contacts` 只更新联系方式，不改动其他答案，也不重新提交问卷）。「拒绝」和「同意」一样需要确认。被拒绝 7 天后可以再次申请（排除再取消排除不会绕过这个等待）。配对解除后，交换同意随之失效、联系方式不再通过系统展示；重新配对后需要重新申请。重新配对不会再次发送「互相感兴趣」通知或邮件。
- 排除某人时，系统同时把排除者对对方的选择记为「不感兴趣」；取消排除后，需要在「我的 · 推荐偏好」中放回推荐才会再次出现。
- 举报私聊消息时，系统只把被举报的那条消息原文存入举报记录的独立字段，管理员看不到其他聊天记录；举报人填写的说明与留存原文分开保存，无法伪造。
- 所有举报（主页、招募、社区帖子、评论、打卡、私聊消息）都遵循同一规则：只能举报此刻自己看得到的内容，看不到的（未公开、被撤下、已删除、互相排除）与不存在的返回同样的结果；举报时由服务器留存内容原文（主页为当时对外展示的文字与公开照片文件名，招募为全文），作者事后修改、删除或撤回不影响管理员核实。

## 校园社区

- **聊天区**：帖子标题选填（≤ 60 字），正文 1–2000 字，最多 4 张图片（本人上传的社区图片）。可编辑、删除自己的帖子，评论（1–500 字）、点赞，新评论会通知作者。帖子只显示系统昵称；作者主页对你可见时才能点进主页。
  右下角绿色叶芽「+」打开发布弹窗，移动端为底部抽屉；收起会保留当前账号的草稿。
- **帖子检索**：社区关键词和高级检索专门搜索帖子标题 / 正文，也可按作者已公开主页的专业、院系、性别、年级、学习方式、地点、目标、科目等筛选；作者主页对你不可见时，作者条件视为未命中。
- **找同学**：独立入口 `/match/search` 支持关键词与高级筛选，可按专业、院系、年级、学习类型、地点、目标、科目、状态、时间、学习模式、频率、时长、兴趣及搭子期待等查找；切换关键词不会跳到帖子结果。隐藏性别不会通过性别检索泄露。
- 两类高级检索都支持「加分 / 必须 / 排除」：精确匹配需符合超过半数的加分条件（`floor(n/2) + 1`），模糊匹配符合任意一项即可；「必须」与「排除」始终生效。科目条件与匹配算法使用同一套严格的科目等价表（`shared/subjects.ts`，如线代 = 线性代数、雅思 = IELTS），不会把「刷题」「建模」这类检索同义词当成同一门课。
- **打卡区**：见下文。可以选择所有同学可见，或仅互相感兴趣的搭子可见；显示连续打卡天数（按北京日期）。
- **招募**：原活动大厅，保留招募、编辑、结束、删除与感兴趣功能。

## 学习打卡与服务器水印

- 打卡页只通过 `getUserMedia` 调用摄像头实时拍照，**页面没有任何上传或相册入口**；`/api/uploads` 拒绝打卡照片。
  预览必须已经播放且有可读取的视频帧，快门才可用；自动播放受限时提供「开启相机预览」，无帧等待限时 12 秒，相机中断或切回前台可恢复／重试。定位在预览就绪后再申请，避免同时弹出两种权限请求。
- 摄像头开启后领取一次性拍照凭证（3 分钟有效、签发 0.5 秒后才能使用、只存哈希），提交时原子作废；服务器只接受 JPEG（≤ 4MB，宽高 240–2560、不超过 400 万像素），拒绝带相机 EXIF 的图片，每天最多打卡 10 次。
- 照片的解码、盖章与重新编码在工作线程中进行（`server/stampPool.ts`），不占用处理请求的主线程：同时处理的照片数固定（最多 2 张）、排队最多 8 张、单张限时 10 秒，每个账号同时只处理一张；处理能力占满时直接提示稍后再试，不会消耗拍照凭证。
- 服务器收到照片后，在**右下角**盖两行水印：地点（例如「南科大·琳恩图书馆」）和服务器收到照片时的 **北京时间**。水印使用 GNU Unifont 16px 点阵字形，**逐个像素绘制**：每个字形像素按照片中对应区块的平均亮度决定颜色，亮背景涂黑、暗背景涂白。像素块大小为 `max(2, round(短边 / 400))`，随后重新编码（同时去除照片元数据）。客户端提交的任何时间字段都会被忽略。
- 位置可细分到楼栋：目录含一丹／琳恩／涵泳图书馆、教学楼及湖畔、二期、荔园、创园、慧园、欣园各栋宿舍。自动识别使用 WGS84 建筑轮廓；只有定位精度足够、误差范围完全落在唯一建筑内时才写入具体楼名，定位模糊时保留校园级文字，并提示手选。一丹缺少可核实的独立建筑边界，暂时仅支持手选确认。
- 可从楼栋目录手选地点，包括未获得定位权限时；水印明确注明「手选」，服务端只接受目录内 ID 并生成地点文字。关闭地点时为「未提供位置」。**不保存经纬度**，也不会记住上一次手选的楼栋。
- 地点资料与来源见 `shared/data/campusBuildings.json`、`shared/data/campusPlaces.sources.json`。地图数据不能保证室内定位精度，仍需真机在相邻楼栋边缘验证；修改名称后需运行 `scripts/gen-watermark-font.mjs` 重新生成点阵字形（支持官方 Unifont HEX 字体文件）。
- 限制：网页无法从技术上证明照片一定是现场拍摄，脚本化客户端仍可能伪造画面或定位；以上措施只能大幅提高作假成本。

## 隐私与管理

上传的图片单张不超过 5MB，每人每小时最多 60 张，合计不超过 200MB（`UPLOAD_QUOTA_MB`，不含打卡照片）。上传超过 24 小时仍没有被资料、问卷草稿、未删除的帖子或打卡引用，也不在待处理举报的留存内容里的文件，会被定期清理并释放配额。数据目录所在磁盘可用空间低于 1GB（`MIN_FREE_DISK_MB`）时，暂停接收新图片与打卡照片。

照片默认私有，只有主动选择展示、发布主页并完成隐私同意后，其他登录同学才可访问。每次请求原图都会检查权限，图片响应为 `private, no-store`；主页撤回、管理员撤下、关闭照片展示或排除后，对相应同学的原图链接失效。本人和管理员保留查看权限；已被他人保存到设备的副本无法远程收回。

普通公开主页不返回真实姓名、学号或联系方式。招募帖只在作者主页对外可见时带出专业与学习方式；主页撤回、被撤下或撤回隐私同意后，旧招募里只显示系统昵称。真实姓名与身份信息供本人及管理员查看；联系方式须经过双方同意。隐私政策页面为 `/privacy`。

「我的」包含资料与问卷、推荐偏好（感兴趣但对方尚未回应的同学可撤回、不感兴趣或已解除配对的同学可放回推荐、已排除的同学可取消排除）、我的帖子 / 打卡 / 招募 / 收藏、通知及账号设置。注销需验证当前密码，会撤回公开资料、招募、社区帖子、评论和打卡，删除推荐选择记录、本人每日名单、私人备注与课表、私聊配对与消息、上传文件及相关私密资料，撤销会话和联系授权；用户行保留匿名编号以维持审核记录的引用关系，不再保留登录邮箱或密码。

管理员可查看待审核内容（主页、招募、社区帖子、评论、打卡）、处理举报（含私聊消息举报，只显示被举报消息的原文）、撤下 / 恢复内容，设置巡查周期，记录审核时间与原因，并向当事人发送邮件及站内通知。

默认发布策略：主页、招募、社区帖子、评论和打卡说明在创建或修改时进行本地文本筛查，普通内容直接公开，不进入人工待审队列。只有组合规则命中极高风险时才暂存待审，作者能看到状态和原因，其他用户不能访问相关正文、图片或匹配资料。管理员可通过或撤下；已被管理员撤下的内容不能通过修改绕过处理。

筛查使用 MIT 开源 [ahocorasick](https://github.com/BrunoRB/ahocorasick) 的多模式匹配及 `server/contentRisk.ts` 的近距离组合规则，版本 `local-high-risk-rules-v1`。覆盖明确的未成年人性剥削材料传播、毒品／武器交易招揽、带时间与手段的严重暴力威胁及恶意曝光隐私等有限文本模式；普通敏感词、抱怨、政治话题和求助表达不会单独触发。不会发送内容到外部模型，不筛查私密姓名、学号或联系方式。这是保守的规则分流，不是机器学习概率判定，也不保证识别所有风险；本版不做图片视觉识别或 OCR，保留举报和人工巡查补充处理。

## 旧数据升级

首次用本版启动已有数据库时会自动处理旧资料：

1. 保留账号 ID、昵称、文字、联系方式及上传引用，不创建默认密码。
2. 旧的无密码账号必须验证邮箱并设置密码，原来的无密码会话无法继续访问。
3. 资料迁移到 schema v2，旧目标与学习方式映射到新选项。
4. 旧 7×10 时间表只迁移能够完整覆盖新时段的选择，不扩大旧的空闲范围。
5. 旧主页暂时撤回，照片改为默认私有、隐私同意清空。用户检查迁移结果并逐项确认新隐私条款后重新发布。
6. v3 首次启动时，旧的联系申请自动转换一次：发起申请视为发起方「感兴趣」；已接受的申请视为双方感兴趣并建立私聊配对。转换完成后在 `settings` 中记录，之后的启动不会重复转换（否则会恢复用户撤销过的选择）。新增的问卷字段（科目、学习性格等）默认为空，不影响已发布主页的推荐资格。
7. 上传记录补记文件大小（用于每人配额）。启动约一分钟后开始第一次清理：上传超过 24 小时、已不被任何资料、草稿、未删除的帖子或打卡引用的历史文件（例如早已从主页移除的照片、已删除帖子和打卡的图片）会从磁盘删除，**无法恢复**，升级前请先备份 uploads。
8. 自动审核新增 `auto_held` 与 `risk_reasons` 字段。已公开但尚未审核的历史内容会按同样规则分流；普通内容不再占用待审队列，极高风险内容暂存待审。未发布草稿、已删除内容和既有人工审核／撤下决定不被自动恢复或重新发布。

9. 2026-10-07 新增每日推荐名单、私人备注与私人课表数据表。旧「稍后再看」记录保留为永久待办，个人模型忽略其旧特征，旧全站先验重新按有效的感兴趣 / 不感兴趣样本处理；新版本不会自动为已领完的当天名单补位。

**首次启动升级前，应备份数据库与 uploads。** 回退旧代码可能恢复旧的隐私行为，不能作为无损回滚方式；恢复数据应使用同一时间点的完整备份并按部署说明验收。部署与运行配置见 [部署说明](docs/deployment.md)。
