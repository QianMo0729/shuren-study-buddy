# 树仁搭子 · 学习搭子匹配系统

在线访问：**[pair.moorn.online](https://pair.moorn.online/)**

面向南方科技大学学生的学习搭子广场。学生验证校园邮箱并设置密码后，先完成个人资料、学习目标和时间安排问卷。提交发布后，系统按问卷计算搭子推荐；也可继续通过关键词与高级检索主动寻找搭子。联系方式只在联系申请被接受后向双方开放。

本版按照《搭子匹配系统功能设计_排版优化版》重构。账号流程采用用户指定的 Resend 邮箱验证码激活与自主设置密码，不生成初始密码。当前版本已部署到上方站点，IPv4、IPv6、HTTPS 与证书续期演练均已验证；邮件服务器认证通过，实际收件仍需单独验收。

## 本地运行

需要 **Node.js ≥ 22.13**，数据库使用 Node 内置 `node:sqlite`。

```sh
npm install
cp .env.example .env
npm run dev
```

前端为 `http://localhost:5173`，API 为 `http://localhost:8787`。不配置发信凭据时，本机开发可获取测试验证码；生产环境始终禁止验证码回显。

```sh
npm run seed       # 可选，仅供本地演示
npm test           # 自动化验证，使用隔离的临时数据库并关闭真实发信
npm run typecheck
npm run build
```

演示管理员学号为 `12310000`，空白演示学号为 `12210001`。演示账号也需要通过「激活账号」设置自己的密码；没有统一演示密码。`npm run seed -- --reset` 会清空所配置的数据目录中的数据库内容，只能用于本地演示。不要将本机 `.env` 或 `data/` 放入生产发布包。

## 账号与邮件

- **首次激活**：输入 8 位数字学号，验证码发送至 `<学号>@mail.sustech.edu.cn`。验证通过后，两次输入自己的新密码，完成激活并进入问卷。
- **以后登录**：使用完整校园邮箱与密码。未完成问卷的账号先进入问卷引导；完成问卷后可进入广场及推荐。
- **忘记或修改密码**：通过校园邮箱验证码重新设置密码，成功后全部旧会话失效，需重新登录。
- 密码至少 8 个字符，包含英文字母与数字，最多 72 个 UTF-8 字节；服务端保存 bcrypt 哈希。
- 验证码与激活凭证有效期为 10 分钟、只能使用一次。验证码区分激活与重置用途；同一邮箱同一用途发送间隔 60 秒，每小时最多发送 5 次，单个验证码最多试错 5 次。登录、发码等接口另有频率限制。
- 验证邮箱本身不会获得登录态，必须完成密码设置。旧版验证码直接登录接口返回 410。
- Cookie 为 HttpOnly、SameSite=Lax，HTTPS 环境附带 Secure；认证响应不缓存。

推荐在私有环境文件中配置：

```dotenv
RESEND_API_KEY=
MAIL_FROM=no-reply@your-verified-domain.example
APP_URL=https://your-site.example
ADMIN_EMAILS=
```

将实际 API Key 填入私有配置，发件地址须使用自己的已验证域名。配置完整时优先通过 Resend API 发信；未配置 API 时可沿用 Resend SMTP：

```dotenv
SMTP_HOST=smtp.resend.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_REQUIRE_TLS=true
SMTP_USER=resend
SMTP_PASS=
MAIL_FROM=no-reply@your-verified-domain.example
```

API 发送失败不会自动切换 SMTP，避免重复投递。邮件包括激活验证码、重置验证码、联系申请提醒与管理员撤下通知。生产未配置邮件服务时，发码返回 503；投递失败返回 502，未送达验证码会失效。本地开发日志不代表真实邮件送达。

`ADMIN_EMAILS` 是逗号分隔的完整校园邮箱列表。名单内账号完成激活或密码登录后获得管理员角色；从名单移除不会自动撤销数据库中已有管理员权限。

## 资料问卷与发布

问卷按 A–F 六个模块组织：

| 模块 | 内容 |
|---|---|
| A · 身份与展示 | 系统固定随机昵称、真实姓名、自动获取的学号、微信与 QQ、是否在双方确认后交换校园邮箱 |
| B · 基础画像 | 性别、年级、自由填写的专业 / 院系，均为选填 |
| C · 状态与目标 | 生活照片、近期学习目标、多选目标对应的补充内容、卡片上的一句话描述、目前状态 |
| D · 时间、地点与方式 | 我的地点与期望地点、我的空闲时间与期望时间、共同学习方式、学习模式、频率与单次时长 |
| E · 学科与期待 | 对搭子的期待、自我介绍 |
| F · 补充与隐私 | 雷区、自由填写的 MBTI、兴趣、照片展示意愿、四项隐私确认 |

发布需完成真实姓名、近期目标、地点、空闲时间、共同学习方式和四项隐私确认。性别、年级、专业、照片、自我介绍和联系方式不作为发布必填项。昵称固定分配，学号由登录邮箱派生，不能通过表单改写。

时间表为 **7 天 × 9 个时段**：08–10、10–12、12–14、14–16、16–18、18–20、20–22、22–24，以及当日 00–08 的通宵时段。填写期望搭子的时间后，与自己的实际时间取交集作为对比范围；不填写时使用自己的全部空闲时间。

填写过程中可以「保存草稿」；点击「提交问卷并匹配」时，先校验必填内容，确认公开范围后保存并发布，再进入推荐结果。支持本地草稿、完成度目录、卡片预览、照片上传与排序。完整问卷保存为草稿即可标记为已完成，但必须确认发布后才会参与推荐。保存已公开资料时，如果删除必填内容或撤销隐私确认，主页会自动撤回，问卷完成状态也会重新变为未完成。

## 问卷推荐

推荐接口为 `GET /api/profiles/recommendations`。每次读取都根据当前保存的问卷计算，不使用随机结果或训练模型；更新问卷后无需重新登录即可重新比较。`/api/auth/me` 中的 `questionnaireComplete` 表示问卷已经保存且必填项完整，与是否公开发布分别判断。

推荐前先检查资格：本人需要已保存完整问卷并发布主页，状态为「正在找搭子」或「已有搭子，仍可再约」。候选同学需要已激活、已设置密码、问卷已保存且完整、主页公开、未被撤下、四项隐私同意完整且处于上述可约状态。系统排除自己、任意方向的排除关系、已经拒绝的联系申请，以及没有共同有效空闲时间的对象。已有待处理或已接受的联系申请不会被自动删除。

仅把照片设为私有不会影响推荐资格；推荐卡片不包含私照地址、真实姓名、学号、邮箱或联系方式。推荐本身不会发送联系申请或邮件，是否联系仍由用户决定，并沿用双方确认后交换联系方式的流程。

评分版本为 `rules-v1`，由以下七项加权组成：

| 维度 | 权重 | 比较规则 |
|---|---:|---|
| 共同时间 | 35 | 双方各自用实际空闲时间与期望时间取交集；再比较共同时间格占比与共同格数 |
| 近期目标 | 25 | 目标选项集合的相似度 |
| 学习相处方式 | 15 | 同一选项为 1；「灵活」与具体方式为 0.6；其余不同选项为 0 |
| 学习地点 | 10 | 综合双方实际地点、各自期望对方地点与对方实际地点、双方期望地点的相似度；「不限」兼容具体地点 |
| 学习方法 | 5 | 双方已填写的学习方法集合相似度 |
| 学习节奏 | 5 | 比较双方都填写的频率、单次时长；同选项为 1，「不定期」与具体频率为 0.5 |
| 兴趣 | 5 | 双方已填写的兴趣集合相似度 |

集合相似度使用 `2 × 交集数量 / 双方选项数量之和`。双方都选择「其他」但未补充内容时不算相同；有补充时，经过全角兼容、大小写与空白标准化后，文字完全相同才算相同。自由填写的自我介绍、MBTI、真实身份、性别和联系方式不进入自动推荐评分。

时间相似度为 `0.7 × 共同时间格 Dice 相似度 + 0.3 × min(共同格数 / 3, 1)`。通宵在评分时与其他时段一样算一格，展示共同小时数时仍按实际 8 小时计算，避免通宵长度带来不成比例的加分。重复或越界时间格不参与计算。

每项相似度保留四位小数，总分为 `四舍五入(100 × Σ(权重 × 相似度) / 可比较权重之和)`。选填项在任一方缺少可比信息时不计入分母，不把未填写当作不匹配；页面同时显示信息覆盖权重及需要进一步沟通的项目。全部选填比较项缺失时，可比较权重为 85/100。**分数表示已填写问卷的相容程度，不是成功匹配概率**；信息较少时，较高分数也只代表已有信息相近。

结果依次按总分、可比较信息覆盖权重、共同小时数降序排列，同值时按固定用户编号升序，最多返回前 20 位。响应区分问卷未完成、尚未发布、当前不可参与、暂无候选人与暂无共同时间等状态，避免把所有空结果都显示为同一种原因。每张推荐卡提供分项依据、共同时间和沟通提示，用户可以查看详情或发起联系申请。

## 检索与联系

- 桌面左侧为检索条件，手机使用筛选抽屉。
- 关键词**只检索自我介绍**，保留同义词扩展；专业、目标和标签使用独立条件。
- 精确匹配需符合超过半数的「加分」条件，模糊匹配符合任意一项即可。「必须」与「排除」条件始终生效。结果按符合条件数排序。
- 支持性别、专业、年级、学习类型、目标、状态、时间、学习模式、频率、时长、兴趣及搭子期待等。MBTI 仅在详情展示，不提供标准检索。
- 查看详情时突出符合条件的内容。可以收藏主页、申请联系或排除对方。
- 联系申请会产生站内提醒并尝试发送邮件。接收方可接受或拒绝；仅接受后，双方才可查看彼此联系方式。校园邮箱还需资料中的独立展示选择。
- 排除是双向可见性限制，对方不会收到排除通知。既有联系授权与相互收藏会撤销；可以在「我的」中管理自己排除的同学。

## 隐私与管理

照片默认私有，只有主动选择展示、发布主页并完成隐私同意后，其他登录同学才可访问。每次请求原图都会检查权限，图片响应为 `private, no-store`；主页撤回、管理员撤下、关闭照片展示或排除后，对相应同学的原图链接失效。本人和管理员保留查看权限；已被他人保存到设备的副本无法远程收回。

普通公开主页不返回真实姓名、学号或联系方式。真实姓名与身份信息供本人及管理员查看；联系方式须经过双方同意。隐私政策页面为 `/privacy`。

「我的」支持联系申请、收藏、活动及账号设置。注销需验证当前密码，会撤回公开资料与帖子、撤销会话和联系授权、删除上传文件及相关私密资料；用户行保留匿名编号以维持审核记录的引用关系，不再保留登录邮箱或密码。

管理员可查看待审核内容、处理举报、撤下 / 恢复主页和活动，设置巡查周期，记录审核时间与原因，并向当事人发送邮件及站内通知。活动大厅保留招募、编辑、结束、删除与感兴趣功能。

## 旧数据升级

首次用本版启动已有数据库时会自动处理旧资料：

1. 保留账号 ID、昵称、文字、联系方式及上传引用，不创建默认密码。
2. 旧的无密码账号必须验证邮箱并设置密码，原来的无密码会话无法继续访问。
3. 资料迁移到 schema v2，旧目标与学习方式映射到新选项。
4. 旧 7×10 时间表只迁移能够完整覆盖新时段的选择，不扩大旧的空闲范围。
5. 旧主页暂时撤回，照片改为默认私有、隐私同意清空。用户检查迁移结果并逐项确认新隐私条款后重新发布。

**首次启动升级前，应备份数据库与 uploads。** 回退旧代码可能恢复旧的隐私行为，不能作为无损回滚方式；恢复数据应使用同一时间点的完整备份并按部署说明验收。部署与运行配置见 [部署说明](docs/deployment.md)。
